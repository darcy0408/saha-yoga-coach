# Implementation report

Last updated: 2026-08-24. An earlier version of this report described the phase before live inference was connected; it survives in git history.

```text
Build status: PASS on Temurin JDK 26.0.1; Gradle configuration cache is disabled because the OpenJFX run task is incompatible with it (build caching is on — note that a cached `clean test` can report success in under a second without executing anything; verify with --no-build-cache --rerun-tasks when the count matters).
Test status: PASS — 123 tests in 24 classes, 0 failures, 0 skipped, with the Lightning model and the Thunder candidate both present so every estimator fixture runs against real weights rather than skipping (a clone without the optional Thunder candidate runs 122 and skips 1). Coverage spans geometry, confidence thresholds, cue limits, instruction-only truthfulness, reference poses on either lead side, deliberate deviations, routine generation/intensity/navigation, personalization, persistence, illustration approval, asset checksums, camera-frame validation, landmark smoothing, the person-crop geometry and its image transform, and Java 26 lazy initialization.
Implemented features: JavaFX onboarding, opt-in local camera practice with live MoveNet inference, a twenty-pose beginner routine in seven phases, spoken guidance with an arrival chime, teaching cards with reviewed illustrations, calibration, synthetic-landmark demo fallback, pause/repeat/skip/easier/stop, derived local history, explainable personalization, progress and deletion, licensed-asset review, an in-practice diagnostics view (raw model scores, the crop region, per-frame cost), and documentation.
Java 26 features used: Java 26 Gradle toolchain and JavaFX 26 verified on Temurin 26.0.1; preview LazyConstant for the initialize-once pose catalog; FFM memory-mapped model load in a confined Arena; records; sealed three-state analysis results with exhaustive pattern matching; virtual threads for the speech helper's reader and writer. Camera capture deliberately uses a platform thread: its loop is blocking native calls, which would pin a virtual carrier.
Pose model: MoveNet SinglePose Lightning ONNX, fetched by scripts/fetch-model.ps1 against a pinned SHA-256, never bundled. The model is shown a square region cropped to the person (from the previous frame's keypoints; whole frame until a body is found), and capture negotiates the largest 4:3 mode the device offers — 1280x960 on the development machine. See docs/model-card.md.
Supported poses: twenty, from Mountain through Final Rest; a measured subset earns angle feedback and the rest explicitly say "instruction only" rather than implying alignment was checked.
Privacy behavior: Local processing; no frame/image/coordinate persistence; derived metrics only at ~/.saha/sessions.json; no upload; in-app deletion.
Known limitations: the person crop and the higher capture size have not yet been watched on a live camera with a person in front of them; camera coaching has been validated against one person, one room, one machine; floor poses are the least supported; single-view 2D angles cannot resolve depth. The full list is in README.md, which is kept current.
Demo instructions: Run gradlew.bat run on JDK 26, accept onboarding, start the practice with or without the model on disk (camera coaching with it, demo landmarks without), observe a low-confidence pause, request an easier option, skip poses, stop, inspect/delete progress. gradlew visionBench times the per-frame pipeline cost; gradlew cameraCheck reports what the machine's cameras can deliver.
Recommended next improvement: a live-camera session with a person in frame, which is the one check that decides whether the crop recovers overhead wrists and seated legs — nothing else in the vision pipeline should move until it happens.
```
